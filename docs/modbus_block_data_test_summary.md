## 模块结构分析结果

### 1. 通讯层 (`dgiot_modbusrtu_tcp.erl`)
- **状态**: ✅ 完整
- **功能**: 接收原始TCP数据，构建Things格式，转发到任务通道
- **关键函数**: `handle_info/2`, `send_aggregated_device_report/5`
- **符合架构**: 严格遵守七层架构，只负责数据转发，不进行解析

### 2. 协议层 (`modbus_rtu.erl`)
- **状态**: ✅ 完整
- **功能**: 解析Modbus RTU协议，支持数据块模式
- **关键函数**: `parse_frame/3`, `decode_data/5`, `is_data_block_mode/3`
- **数据块处理**: 支持`modbus_rtu_data_blocks:process_data_blocks/2`

### 3. 数据块处理模块 (`modbus_rtu_data_blocks.erl`)
- **状态**: ✅ 存在
- **功能**: 处理数据块模式，计算派生属性
- **关键函数**: `process_data_blocks/2`

### 4. 业务层 (`dgiot_task.erl`)
- **状态**: ✅ 完整
- **功能**: 计算派生属性，调用公式计算器，保存数据
- **关键函数**: `get_calculated/4`, `save_td/4`

### 5. 公式计算器 (`dgiot_formula_calculator_simple.erl`)
- **状态**: ✅ 存在
- **功能**: 计算物模型中的公式表达式
- **关键函数**: `calculate_formula/3`

## 数据上报流程（七层架构）

### 完整数据流
```
设备 → 通讯层 → 协议层 → 业务层 → 数据层 → 缓存层 → API层 → 前端
```

### 各层详细职责

| 层级 | 模块 | 职责 | 关键操作 |
|------|------|------|----------|
| 通讯层 | `dgiot_modbusrtu_tcp` | 接收原始数据 | `build_raw_data_things/5` |
| 协议层 | `modbus_rtu` | 解析协议 | `parse_frame/3`, `is_data_block_mode/3` |
| 业务层 | `dgiot_task` | 计算属性 | `get_calculated/4`, `save_td/4` |
| 数据层 | `dgiot_tdengine_adapter` | 存储数据 | `save/3` |
| 缓存层 | `dgiot_data` | 缓存数据 | `put/2`, `get/1` |
| API层 | API模块 | 提供接口 | 设备卡片API |
| 展示层 | 前端 | 展示数据 | 实时数据卡片 |

## 问题排查指南

### 常见问题及解决方案

#### 问题1: 数据未上报
**症状**: 设备连接正常，但数据未进入系统
**排查步骤**:
1. 检查通讯层日志: `tail -f logs/console.log | grep "Received data"`
2. 验证设备注册: 查看注册报文是否正确解析
3. 检查通道配置: 验证产品通道配置

#### 问题2: 只解析出block_data，没有派生属性
**症状**: 基础属性正常，计算值属性为空
**排查步骤**:
1. 检查物模型配置: `strategy`字段是否为"计算值"
2. 验证数据源配置: `dataSource.key`是否正确指向`block_data`
3. 测试公式计算器: 手动测试公式计算功能

#### 问题3: API查询返回空数据
**症状**: API调用成功，但返回数据为空
**排查步骤**:
1. 检查缓存数据: `dgiot_data:get({last_data, DeviceId})`
2. 验证设备ID: 确保查询的设备ID正确
3. 检查API认证: 验证token有效性

#### 问题4: 公式计算错误
**症状**: 派生属性计算不正确
**排查步骤**:
1. 检查公式语法: 验证公式格式是否正确
2. 验证变量名: 确保变量名与数据源匹配
3. 查看计算器日志: 检查公式计算过程
