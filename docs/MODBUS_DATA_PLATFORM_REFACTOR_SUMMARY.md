# Modbus插件数据中台架构重构总结

## 项目背景

基于用户提出的"DG-IoT定位是数据中台，做数据汇聚"的核心定位，对Modbus插件进行了全面的架构重构，从通用插件架构转变为专注于数据汇聚的数据中台架构。

## 重构原则

### 1. 数据中台定位
- **数据汇聚中心**：作为数据接收方，汇聚外部设备数据
- **被动接收为主**：外部设备主动上报，我们被动接收
- **协议适配**：根据外部设备角色适配通信模式

### 2. 协议角色匹配原则
```
外部设备角色  →  DG-IoT角色  →  通信方向
-------------------------------------------
Modbus RTU Client → RTU Server → 设备→中台
Modbus TCP Server → TCP Client → 中台→设备
```

### 3. 架构简化原则
- **通道统一放置**：所有通道文件放在src根目录
- **文件名明确**：清晰标识协议和角色
- **职责单一**：每个文件功能明确

## 重构成果

### 1. 最终目录结构
```
src/
├── dgiot_modbus_rtu_server_channel.erl    # RTU服务器通道（数据入口）
├── dgiot_modbus_tcp_client_channel.erl    # TCP客户端通道（数据入口）
├── modbus_rtu/server/dgiot_modbus_rtu_server.erl  # RTU服务器主模块
├── modbus_tcp/client/dgiot_modbus_tcp_client.erl  # TCP客户端主模块
└── common/                                # 通用模块
    ├── dgiot_modbus.erl                   # 插件主模块
    ├── dgiot_modbus_app.erl               # 应用模块
    ├── dgiot_modbus_sup.erl               # 监控树
    ├── dgiot_modbus_handler.erl           # HTTP处理器
    └── modbus/                            # 协议解析工具
```

### 2. 通道文件说明
- **RTU服务器通道** (`dgiot_modbus_rtu_server_channel.erl`)：接收串口设备数据
- **TCP客户端通道** (`dgiot_modbus_tcp_client_channel.erl`)：拉取网络设备数据

### 3. 删除的不必要组件
- RTU客户端通道（外部设备是Client，我们不需要Client）
- TCP服务器通道（外部设备是Server，我们不需要Server）
- 复杂的目录层级（简化结构）
