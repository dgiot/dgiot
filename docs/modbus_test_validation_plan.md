# Modbus RTU 测试验证方案

## 概述

本文档定义了Modbus RTU模块的完整测试验证方案，确保七层架构的每一层都能正确工作，并且从设备到API的完整数据流能够正常运行。

## 1. 测试目标

### 1.1 总体目标
- 验证七层架构的每一层功能正确
- 确保从设备到API的完整数据流畅通
- 验证三种注册方式的正确性
- 确保上下行消息路由正常
- 验证API能够查询到设备上报的数据

### 1.2 具体目标
1. **通讯层**: 验证TCP连接管理、三种注册方式、原始数据转发
2. **协议层**: 验证Modbus RTU协议解析、数据封包/解包、CRC校验
3. **消息路由层**: 验证MQTT消息路由、任务队列管理、父设备消息汇聚
4. **业务层**: 验证数据解码、属性计算、告警处理、设备状态管理
5. **数据层**: 验证TDengine数据存储、时序数据管理
6. **缓存层**: 验证实时数据缓存、设备状态缓存
7. **API层**: 验证实时数据查询、历史数据查询、设备状态查询

## 2. 测试环境

### 2.1 硬件环境
- Modbus RTU设备模拟器（或真实设备）
- TCP服务器（DG-IoT平台）
- 测试客户端（API调用）

### 2.2 软件环境
- DG-IoT平台（运行Modbus插件）
- TDengine数据库
- MQTT Broker
- 测试工具（Postman、curl、自定义测试脚本）

### 2.3 测试数据
- 模拟Modbus RTU数据包
- 测试产品配置（物模型）
- 测试设备信息

## 3. 测试用例设计

### 3.1 通讯层测试用例

#### 测试用例1: TCP连接管理
- **测试目标**: 验证TCP连接的建立、维护和断开
- **测试步骤**:
  1. 模拟设备连接到TCP服务器
  2. 验证连接成功建立
  3. 发送心跳包保持连接
  4. 主动断开连接
  5. 验证连接正确断开
- **预期结果**: 连接状态正确管理，日志记录完整

#### 测试用例2: RegisterByIp注册
- **测试目标**: 验证基于IP地址的注册方式
- **测试步骤**:
  1. 配置产品使用RegisterByIp注册方式
  2. 模拟设备连接（固定IP）
  3. 验证设备正确注册
  4. 验证设备地址为IP地址
- **预期结果**: 设备成功注册，设备地址为IP地址

#### 测试用例3: RegisterByPort注册
- **测试目标**: 验证基于端口+注册报文的注册方式
- **测试步骤**:
  1. 配置产品使用RegisterByPort注册方式
  2. 模拟设备发送注册报文
  3. 验证设备正确注册
  4. 验证设备地址为"注册报文-端口号"
- **预期结果**: 设备成功注册，设备地址格式正确

#### 测试用例4: RegisterByRegular注册
- **测试目标**: 验证基于正则表达式的注册方式
- **测试步骤**:
  1. 配置产品使用RegisterByRegular注册方式
  2. 配置正则表达式匹配规则
  3. 模拟设备发送匹配的注册报文
  4. 验证设备正确注册
  5. 模拟设备发送不匹配的注册报文
  6. 验证设备注册失败
- **预期结果**: 正则匹配正确，设备注册成功/失败符合预期

#### 测试用例5: 原始数据转发
- **测试目标**: 验证通讯层只转发原始数据，不进行解码
- **测试步骤**:
  1. 模拟设备发送Modbus RTU数据包
  2. 验证通讯层接收原始数据
  3. 验证通讯层将数据打包为标准格式转发
  4. 验证通讯层没有调用`modbus_rtu:parse_frame`
- **预期结果**: 原始数据正确转发，格式符合标准

### 3.2 协议层测试用例

#### 测试用例6: Modbus RTU协议解析
- **测试目标**: 验证Modbus RTU协议正确解析
- **测试步骤**:
  1. 准备测试数据包（各种功能码）
  2. 调用`modbus_rtu:parse_frame`解析数据
  3. 验证解析结果正确
  4. 验证CRC校验正确
- **预期结果**: 数据包正确解析，CRC校验通过

#### 测试用例7: 多种数据格式支持
- **测试目标**: 验证多种数据格式的解析
- **测试步骤**:
  1. 测试raw格式：验证原始二进制数据返回
  2. 测试bit格式：验证位数据正确解析
  3. 测试short16格式：验证16位有符号整数解析
  4. 测试ushort16格式：验证16位无符号整数解析
  5. 测试long32格式：验证32位有符号整数解析
  6. 测试ulong32格式：验证32位无符号整数解析
  7. 测试float32格式：验证32位浮点数解析
- **预期结果**: 各种数据格式正确解析

#### 测试用例8: 数据封包
- **测试目标**: 验证Modbus RTU请求帧构建
- **测试步骤**:
  1. 准备数据源配置
  2. 调用`modbus_rtu:to_frame`构建请求帧
  3. 验证构建的请求帧格式正确
  4. 验证CRC校验码正确计算
- **预期结果**: 请求帧正确构建，符合Modbus RTU协议

## 4. 端到端测试场景

### 4.1 场景一：完整数据流测试
**测试目标**: 验证从设备到API的完整数据流

**测试步骤**:
1. 配置产品（使用RegisterByPort注册方式）
2. 模拟设备连接并发送注册报文
3. 验证设备成功注册
4. 模拟设备发送Modbus RTU数据包
5. 验证数据经过七层架构处理
6. 调用API查询设备数据
7. 验证API返回的数据正确

**验证点**:
- 设备注册成功
- 数据正确解析
- 属性正确计算
- 数据正确存储
- 缓存正确更新
- API正确返回数据

### 4.2 场景二：三种注册方式对比测试
**测试目标**: 验证三种注册方式的差异和正确性

**测试步骤**:
1. 分别配置三个产品使用不同的注册方式
2. 模拟三种设备分别连接
3. 验证每种注册方式的设备地址生成
4. 模拟数据上报
5. 验证数据正确处理

**验证点**:
- RegisterByIp: 设备地址为IP地址
- RegisterByPort: 设备地址为"注册报文-端口号"
- RegisterByRegular: 设备地址为注册报文
- 各种注册方式的数据处理一致

### 4.3 场景三：大规模设备压力测试
**测试目标**: 验证系统支持大规模设备连接和数据上报

**测试步骤**:
1. 模拟1000个设备同时连接
2. 模拟设备周期性数据上报
3. 监控系统资源使用情况
4. 验证数据处理的正确性
5. 验证API查询性能

**验证点**:
- 系统稳定运行
- 数据处理正确
- 资源使用合理
- API响应时间可接受
