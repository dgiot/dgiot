# CodeAI规则和工作流设计

## 概述

本目录包含为CodeAI（AI助手）设计的规则和工作流配置，专门针对DG-IoT物联网平台开发优化。合理的规则设置可以显著提高开发效率和代码质量。

## 目录结构

```
.clinerules/
├── README.md                    # 规则说明文档（本文件）
├── general_rules.md            # 通用开发规则
├── coding_standards.md         # 编码规范
├── project_specific/           # 项目特定规则
│   ├── dgiot_drone.md          # 无人机插件规则
│   ├── dgiot_modbus.md         # Modbus插件规则（已有）
│   └── dgiot_tdengine.md       # TDengine规则
├── workflows/                  # 工作流定义
│   ├── plugin_development.md   # 插件开发工作流
│   ├── testing_framework.md    # 测试框架工作流
│   └── deployment.md           # 部署工作流
└── templates/                  # 代码模板
    ├── new_plugin.md
    ├── test_case.md
    └── api_design.md
```

## 规则类型

### 1. 通用规则 (general_rules.md)
- 适用于所有DG-IoT项目的开发规范
- 热编译/热加载命令
- 日志格式标准
- API调试流程

### 2. 编码规范 (coding_standards.md)
- Erlang/OTP编码规范
- 函数命名约定
- 模块组织结构
- 注释和文档要求

### 3. 项目特定规则 (project_specific/)
- 针对特定插件的开发规则
- 协议解析规范
- 测试数据管理
- 部署配置

### 4. 工作流定义 (workflows/)
- 标准化开发流程
- 自动化任务编排
- 质量保证步骤
- 部署验证流程

### 5. 代码模板 (templates/)
- 新插件模板
- 测试用例模板
- API设计模板
- 配置模板

## 使用方式

### 对于CodeAI（AI助手）
CodeAI会自动读取这些规则文件，并根据规则提供：
1. 符合规范的代码建议
2. 标准化的开发流程指导
3. 正确的命令和工具使用
4. 质量保证检查

### 对于开发者
1. **查看规则**：阅读相关规则文件了解标准
2. **请求协助**：向CodeAI提出符合规则的问题
3. **遵循工作流**：按照定义的工作流进行开发
4. **使用模板**：基于模板快速开始新任务

## 示例

### 请求CodeAI协助开发新插件：
```
用户：请帮我创建一个新的DG-IoT插件，协议类型是XXX
CodeAI（根据规则）：按照插件开发工作流，先创建目录结构，然后编写协议解析，最后设置测试框架
```

### 请求CodeAI分析报文：
```
用户：请帮我分析这个无人机协议报文
CodeAI（根据规则）：首先运行智能扫描工具，然后解析Wireshark文件，最后生成测试报告
```

## 维护和更新

1. **添加新规则**：在相应目录创建新的.md文件
2. **更新现有规则**：直接编辑对应文件
3. **验证规则**：确保规则与实际开发流程一致
4. **同步到团队**：通过版本控制共享规则更新

## 最佳实践

1. **规则要具体**：提供明确的命令和示例
2. **工作流要完整**：覆盖从需求到部署的全过程
3. **模板要实用**：提供可直接使用的代码片段
4. **保持更新**：随着技术栈变化更新规则
