
# DG-IoT通用开发规则

## 概述

本文件定义了DG-IoT平台开发的通用规则，适用于所有插件和模块的开发工作。

## 编译命令规范

### ✅ 允许使用的命令
1. **`make`** - 全量编译检查，验证编译是否通过
2. **`make run`** - 全量编译并启动在线调试环境

### ❌ 禁止使用的命令
1. **`make compile`** - 此命令不存在或不支持
2. **`erl`** - 禁止直接使用erl命令，必须使用平台提供的热编译和热加载命令

### 🔥 日常开发推荐
```bash
# 热编译
_build/emqx/rel/emqx/bin/emqx eval 'dgiot_plugin:compile(dgiot).'

# 热加载
_build/emqx/rel/emqx/bin/emqx eval 'dgiot_plugin:reload_plugin(dgiot).'
```

### ⚠️ 热编译质量要求
- **零警告原则**：热编译必须消除所有编译警告
- **检查清单**：
  - [ ] 没有未使用变量警告
  - [ ] 没有未使用函数警告
  - [ ] 没有语法错误
  - [ ] 没有类型不匹配

## 工程建议

### 1. 文件生成策略
- **先生成插件所需要的所有文件**：在全量编译之前，确保所有必要的文件都已创建
- **全量编译之后就不再新增文件**：一旦完成全量编译，后续修改只做热编译
- **全部做热编译**：日常开发中使用热编译提高效率

## 开发工作流

### 1. 需求分析阶段
- **梳理流程和需求** - 在编写代码前，必须先搞清楚业务流程和需求细节
- **看代码理解系统** - 花时间阅读相关代码，理解系统架构和数据流
- **问需求确认细节** - 不确定的地方主动询问，避免盲目开发
- **形成完整方案** - 明确输入、处理、输出三个环节

### 2. 开发实现阶段
- **编写业务模块** - 在正式模块中实现业务逻辑
- **添加日志输出** - 在关键流程节点添加日志，便于调试和监控
- **遵循编码规范** - 遵守编码规范，保证代码质量

### 3. 测试验证阶段
- **使用在线测试函数** - test/0 函数用于在线调测
- **查看日志分析问题** - 通过日志输出分析问题，而非创建测试文件
- **真实数据验证** - 使用真实数据触发，观察日志输出

### 4. 测试用例固化阶段
- **模拟器功能** - test 函数用于模拟设备行为，在开发阶段充当模拟器
- **固化需求** - test 函数将需求固化为可执行的测试用例
- **回归测试** - 测试用例用于后续回归测试，确保功能稳定

### 开发原则
- **先理解后编码** - 搞清楚流程和需求再写代码
- **日志优于测试** - 用日志定位问题，不用测试文件
- **test 函数职责** - test 是模拟器和测试用例，不是调试工具
- **真实数据验证** - 在真实环境中验证，不创建独立测试环境
- **IP绑定模拟现场** - 通过IP绑定将现场环境搬回开发机调测

#***REMOVED***绑定模拟现场环境

### 核心价值
通过绑定现场设备的真实IP地址，在开发机上完整模拟现场环境，实现真实设备通信测试和完整业务流程验证。

### 关键操作
1. **绑定现场IP**：使用脚本批量绑定现场设备IP地址
2. **启动模拟器**：运行PLC和治具模拟器进行测试
3. **闭环调测**：模拟现场 → 热编译 → 日志分析 → 问题定位 → 修改代码
