### 设计原理

**端口即设备类型标识符**：
- 所有设备连接到统一入口端口 `20000`
- 源端口自动识别设备类型
- 目标端口统一为 `20000`

格式：`{源端口, {设备ID, 产品ID, 设备名称, 是否创建设备, 是否是舵面设备}}`

## 关键设计模式

### 1. 端口即设备类型标识符

**原理**：
- 源端口 = 设备类型
- 所有设备连接到统一入口端口 20000
- 服务端根据源端口自动识别设备类型

**优势**：
- 无需复杂的设备发现协议
- 网络拓扑一目了然
- 易于调试和扩展

### 2. 治具地址映射

**原理**：
- 治具地址在PLC寄存器中的地址编号（0-7, 255）
- 用于PLC Modbus寄存器基地址映射

**映射关系**：
- PLC基地址 + 治具地址 = 实际寄存器地址

### 3. PLC分区管理

**分区**：
- **磁航向PLC**（192.168.100.20）：管理磁航向工位（1700）
- **共享PLC**（192.168.100.40）：管理所有其他工位（1100-1600）

**优势**：
- 独立控制，互不干扰
- 易于维护和调试

## 数据流向

### 设备注册流程

```
设备连接 → TCP:20000
    ↓
识别源端口 → 设备类型映射
    ↓
创建设备实体 → DG-IoT设备管理
    ↓
IP→工位映射 → dgiot_uav_station_manager
    ↓
工位→无人机绑定 → 自动化测试
```

### 数据上报流程

```
舵面传感器 (10001-10005) → Modbus RTU
    ↓
单片机 (10006) → 工位绑定 + 继电器上电
    ↓
地测口 (10007) → EB90协议数据
    ↓
数据汇聚 → 无人机物模型
    ↓
存储 → TDengine（时序数据） + Parse Server（业务数据）
```
