# Modbus集成测试用例规范（测试驱动开发）

## 概述

本文档定义了Modbus集成测试的测试用例规范，采用测试驱动开发（TDD）方式：
1. 先定义测试用例
2. 根据测试用例编写代码实现
3. 根据测试用例定义日志规范
4. 验证测试用例通过

## 测试驱动开发流程

```
需求分析 → 编写测试用例 → 运行测试（失败） → 编写实现代码 → 运行测试（通过） → 重构优化
```

## 测试用例实现规范

### 1. 测试脚本结构
```bash
#!/bin/bash
# test_<用例名称>.sh

# 测试用例描述
TEST_CASE_DESCRIPTION="<用例描述>"

# 前置条件检查
check_prerequisites() {
    # 检查测试环境
}

# 测试步骤执行
execute_test_steps() {
    # 执行测试步骤
}

# 预期结果验证
verify_expected_results() {
    # 验证测试结果
}

# 日志规范验证
verify_log_specification() {
    # 验证日志格式和内容
}

# 主函数
main() {
    echo "测试用例: $TEST_CASE_DESCRIPTION"
    check_prerequisites
    execute_test_steps
    verify_expected_results
    verify_log_specification
}
```

### 2. 日志规范实现
```erlang
%% 标准日志格式函数
log_test_case(TestCase, Step, Result, Details) ->
    Timestamp = dgiot_datetime:now_ms(),
    FileLine = ?FILE ++ ":" ++ integer_to_list(?LINE),
    
    LogEntry = #{
        time => Timestamp,
        test_case => TestCase,
        step => Step,
        result => Result,
        details => Details,
        file_line => FileLine
    },
    
    ?LOG(info, "~p", [LogEntry]).
```

### 3. 测试数据管理

- 日志样本文件：`log_samples/`

## 使用说明

1. **新功能开发**：
   ```bash
   # 1. 设计测试用例
   # 2. 编写测试脚本
   # 3. 运行测试（应该失败）
   # 4. 实现功能代码
   # 5. 运行测试（应该通过）
   # 6. 重构优化
   ```

2. **问题修复**：
   ```bash
   # 1. 复现问题的测试用例
   # 2. 编写重现脚本
   # 3. 分析失败原因
   # 4. 修复代码
   # 5. 验证修复
   ```

3. **回归测试**：
   ```bash
   # 运行所有测试用例
   ./run_all_tests.sh
   ```
