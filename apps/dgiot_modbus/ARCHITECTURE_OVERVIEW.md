# Modbus插件架构概述（数据中台版）

## 架构设计理念

### 1. 数据流向
```
外部设备 → 协议适配 → 数据汇聚 → 数据处理 → 数据存储
    ↑           ↑          ↑          ↑          ↑
 RTU Client  RTU Server  通道入口  业务逻辑   TDengine
 TCP Server  TCP Client
```

### 2. 角色定位
- **DG-IoT**：数据中台，数据汇聚中心
- **外部设备**：数据生产者，主动上报或提供数据接口

### 3. 协议适配策略
| 外部设备协议 | 外部设备角色 | DG-IoT角色 | 通信方向 |
|-------------|-------------|------------|----------|
| Modbus RTU  | Client      | Server     | 设备→中台 |
| Modbus TCP  | Server      | Client     | 中台→设备 |

## 核心模块说明

### 1. 通道层（数据入口）
- **RTU服务器通道**：接收串口设备数据
- **TCP客户端通道**：拉取网络设备数据

### 2. 协议层（数据解析）
- **RTU协议解析**：解析串口数据帧
- **TCP协议解析**：解析网络数据包

### 3. 业务层（数据处理）
- **数据解码**：原始数据转换为业务数据
- **属性计算**：计算派生属性值
- **数据存储**：保存到时序数据库

## 文件映射关系

### RTU数据流
```
设备 → dgiot_modbus_rtu_server_channel.erl → dgiot_modbus_rtu_server.erl → modbus_rtu/*.erl → 业务处理
```

### TCP数据流  
```
设备 ← dgiot_modbus_tcp_client_channel.erl ← dgiot_modbus_tcp_client.erl ← modbus_tcp.erl ← 业务处理
```

## 扩展性考虑

### 1. 协议扩展
- 新增协议类型：在common/modbus/下添加新协议解析
- 新增通道类型：在src根目录添加新通道文件

### 2. 功能扩展
- 数据处理：在业务层添加新的处理逻辑
- 数据存储：支持更多存储后端

## 最佳实践

1. **保持通道简洁**：通道只负责数据接收/发送，不处理业务逻辑
2. **协议解析独立**：协议解析模块独立，便于维护和测试
3. **错误处理完善**：每个层级都有完善的错误处理机制
4. **日志记录完整**：关键操作都有日志记录，便于问题排查
