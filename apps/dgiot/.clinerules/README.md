# dgiot核心模块规则

## 概述

本文件定义了dgiot核心模块的开发、测试和部署规则，确保核心模块符合DG-IoT平台的规范和最佳实践。

## 模块信息

### 基本信息
- **模块名称**: dgiot
- **模块类型**: 核心框架
- **主要功能**: 提供DG-IoT平台的核心功能，包括插件管理、通道管理、数据路由等
- **依赖模块**: 无（基础模块）

### 目录结构
```
apps/dgiot/
├── src/                    # 源代码目录
│   ├── dgiot.erl          # 主模块
│   ├── dgiot_plugin.erl   # 插件管理模块
│   ├── dgiot_channelx.erl # 通道管理模块
│   └── ...                # 其他核心模块
├── include/               # 头文件目录
│   └── dgiot.hrl          # 核心头文件
├── c_src/                 # C语言源代码（如有）
├── priv/                  # 私有资源目录
│   ├── config/           # 配置文件
│   └── ...               # 其他资源
└── README.md             # 模块文档
```

## 开发规范

### 代码规范
- 遵循项目统一的编码规范（参考`.clinerules/04_coding_rules.md`）
- 作为核心模块，代码质量要求最高标准
- 错误处理使用`{ok, Result}`和`{error, Reason}`格式
- 日志使用`?LOG`宏，避免直接使用`io:format`

### 架构规范
- 遵循七层架构设计原则（参考`.clinerules/01_architecture_rules.md`）
- 提供清晰的API接口供其他插件调用
- 保持向后兼容性，避免破坏性变更
- 模块间解耦，职责清晰

### 性能规范
- 核心模块性能要求最高
- 避免阻塞操作，使用异步处理
- 合理使用ETS表和缓存
- 监控内存和CPU使用情况

## 测试规范

### 单元测试
- 测试覆盖率要求：≥90%（核心模块要求更高）
- 包含所有边界条件测试
- 包含所有错误场景测试
- 测试数据使用真实场景

### 集成测试
- 测试与其他插件的集成
- 测试完整的数据流
- 测试高并发场景
- 测试故障恢复能力

### 性能测试
- 响应时间要求：<10ms（核心操作）
- 并发连接数：支持10000+连接
- 数据吞吐量：≥10000消息/秒
- 内存使用：稳定可控

## 部署规范

### 配置管理
- 配置文件使用模板格式（`.template`后缀）
- 提供完整的默认配置
- 支持动态配置更新
- 配置验证和错误处理

### 版本管理
- 使用语义化版本号（MAJOR.MINOR.PATCH）
- 重大变更需要提供迁移指南
- 保持API向后兼容
- 提供版本升级脚本

### 依赖管理
- 明确声明所有外部依赖
- 版本号固定，避免自动升级
- 提供依赖安装脚本
- 定期更新安全依赖

## 运维规范

### 监控告警
- 监控核心模块健康状态
- 设置性能告警阈值
- 监控错误率和异常
- 提供运维仪表板

### 日志管理
- 关键操作记录详细日志
- 支持动态调整日志级别
- 日志格式统一规范
- 日志轮转和归档

### 故障处理
- 提供快速故障诊断指南
- 支持热修复和回滚
- 故障恢复自动化
- 定期演练故障场景
