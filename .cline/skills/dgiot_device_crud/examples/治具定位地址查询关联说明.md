# 治具定位地址查询关联功能说明

## 概述

已成功修改`create_all()`函数，添加了治具定位地址查询关联功能。该功能在创建设备之前先查询治具的工位信息，然后根据查询结果创建设备，实现了治具与设备创建的智能关联。

## 修改内容

### 1. 修改后的`create_all()`函数逻辑

```erlang
create_all() ->
    %% 步骤1: 查询治具的定位地址信息
    case query_fixture_workstation_info() of
        {ok, FixtureWorkstations} ->
            %% 步骤2: 合并治具查询结果和预设工位信息
            Workstations = merge_workstation_info(FixtureWorkstations),
            %% 步骤3: 批量创建设备
            batch_create(Workstations);
        {error, Reason} ->
            %% 治具查询失败时使用预设工位信息
            %% 使用预设工位设备列表
            batch_create(PresetWorkstations)
    end.
```

### 2. 新增功能模块

#### 2.1 治具查询功能 (`query_fixture_workstation_info/0`)
- 模拟查询治具的工位代码信息
- 在实际应用中会调用`dgiot_uav_fixture_protocol:read_workstation_info/0`
- 返回治具的工位信息列表

#### 2.2 工位信息合并功能 (`merge_workstation_info/1`)
- 合并治具查询结果和预设工位信息
- 合并策略：优先使用治具查询结果，缺失的使用预设信息
- 添加治具有但预设中没有的工位

#### 2.3 治具工位映射功能 (`map_fixture_code_to_device/3`)
- 将治具工位代码映射到设备类型和地址
- 支持以下工位代码映射：
  - 代码1 → 总测2工位 (D1600)
  - 代码2 → 总测2-动力工位 (D1601)
  - 代码5 → 桁行架工位 (D1100)
  - 代码6 → 拷机2工位 (D1300)
  - 代码7 → 拷机1工位 (D1200)
  - 代码16#FF → 上料台 (FEEDING_TABLE)

## 治具协议关联

### 治具协议命令
在`dgiot_uav_fixture_protocol.erl`中，治具支持以下相关命令：

```erlang
%% 读取工位信息命令
#{id => 14, name => <<"读取工位信息">>, code => <<"read_workstation_info">>, 
  modbus => #{function => 3, address => 16#000D, quantity => 1}}
```

### 治具工位代码解析
治具返回的工位代码对应关系：
- 1 → 总测2
- 2 → 总测2-动力
- 3 → 对总测2
- 4 → 总测2-动力
- 5 → 桁行架
- 6 → 拷机2
- 7 → 拷机1
- 16#FF → 上料台（没有PLC）

## 工作流程

### 正常流程（治具查询成功）
1. 查询治具工位信息
2. 解析治具返回的工位代码
3. 将治具工位代码映射到设备类型和地址
4. 合并治具查询结果和预设工位信息
5. 根据合并后的工位信息创建设备

### 备用流程（治具查询失败）
1. 治具查询失败时记录警告
2. 使用预设的工位信息
3. 根据预设工位信息创建设备
