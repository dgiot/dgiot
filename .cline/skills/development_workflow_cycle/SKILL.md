# 开发工作流循环技能

专注于"编码-编译-日志"三步循环的开发工作流技能，提供高效的开发调试流程和最佳实践。

## 快速开始

当用户需要进行高效的开发调试循环时，激活本技能，专注于编码、编译、日志三个核心步骤。

## 核心概念

### 1. 三步循环定义
```
编码 (Coding) → 编译 (Compilation) → 日志 (Logging)
      ↑                                     ↓
      └─────────── 调试修复 ───────────────┘
```

### 2. 循环目标
- **快速反馈**: 最小化修改到验证的时间
- **问题定位**: 通过日志快速定位问题
- **持续改进**: 基于反馈持续优化代码
- **质量保证**: 确保每次修改都经过验证

### 3. 循环价值
- **效率提升**: 减少上下文切换
- **质量提升**: 即时发现和修复问题
- **知识积累**: 通过日志积累调试经验
- **流程标准化**: 建立可重复的开发流程

## 三步循环详解

### 1. 编码阶段 (Coding)

#### 核心任务
- **功能实现**: 编写新功能代码
- **问题修复**: 修复已知问题
- **代码优化**: 优化现有代码
- **重构改进**: 改进代码结构

#### 最佳实践
```erlang
%% 编码最佳实践
- 小步修改: 每次只修改一个功能点
- 单元测试: 编写对应的测试用例
- 代码审查: 自我审查代码质量
- 文档更新: 更新相关文档注释
```

#### 工具支持
```bash
# 代码编辑器
code .  # VSCode
vim     # Vim编辑器

# 语法检查
erlc -I include/ -o /dev/null file.erl

# 代码格式化
rebar3 fmt
```

### 2. 编译阶段 (Compilation)

#### 核心任务
- **语法检查**: 检查代码语法正确性
- **依赖验证**: 验证模块依赖关系
- **类型检查**: 检查类型一致性
- **编译优化**: 应用编译优化

#### 最佳实践
```bash
# 增量编译
erlc -I include/ -o ebin/ src/module.erl

# 全量编译
make compile

# 插件编译
dgiot_plugin:compile(Module).

# 热编译检查
make hot_compile
```

#### 常见问题解决
```erlang
%% 编译错误处理流程
1. 读取错误信息
2. 定位错误位置
3. 分析错误原因
4. 修改代码
5. 重新编译
```

### 3. 日志阶段 (Logging)

#### 核心任务
- **运行验证**: 验证代码功能正确性
- **问题诊断**: 通过日志诊断问题
- **性能监控**: 监控代码性能表现
- **行为记录**: 记录系统行为

#### 最佳实践
```erlang
%% 日志最佳实践
- 分级日志: 使用不同级别的日志
- 结构化日志: 输出结构化的日志信息
- 上下文信息: 包含足够的上下文信息
- 中文支持: 确保中文正确显示

%% 日志示例
?LOG(debug, "~ts: 开始处理数据, ID=~p", [<<"数据处理">>, DataId]).
?LOG(info, "~ts: 成功处理~p条记录", [<<"数据统计">>, Count]).
?LOG(error, "~ts: 处理失败, 原因=~p", [<<"错误处理">>, Reason]).
```

#### 日志工具
```bash
# 实时日志查看
tail -f log/erlang.log.1

# 日志过滤
grep -i error log/erlang.log.1

# 日志分析
awk '/ERROR/ {count++} END {print "错误数:", count}' log/erlang.log.1

# 性能日志
tail -f log/performance.log
```

## 问题诊断模式

### 1. 编译问题诊断
```
症状: 编译失败
诊断步骤:
1. 查看编译错误信息
2. 定位错误文件和行号
3. 分析语法或依赖问题
4. 检查头文件包含
5. 验证环境配置
```

### 2. 运行时问题诊断
```
症状: 运行时报错或异常
诊断步骤:
1. 查看错误日志
2. 分析堆栈跟踪
3. 检查输入数据
4. 验证状态一致性
5. 使用调试工具
```

### 3. 性能问题诊断
```
症状: 性能下降
诊断步骤:
1. 查看性能日志
2. 分析关键路径
3. 检查资源使用
4. 识别瓶颈点
5. 优化算法或配置
```

## 最佳实践总结

### 1. 编码阶段
- **小步快跑**: 每次修改尽量小，便于定位问题
- **测试驱动**: 先写测试，再实现功能
- **代码审查**: 自我审查或同伴审查
- **文档同步**: 代码和文档同步更新

### 2. 编译阶段
- **增量编译**: 开发时使用增量编译提高效率
- **错误处理**: 仔细分析编译错误，不忽略警告
- **环境一致**: 确保开发、测试、生产环境一致
- **版本控制**: 编译时记录版本信息

### 3. 日志阶段
- **分级管理**: 合理使用debug/info/warn/error级别
- **结构化输出**: 便于机器解析和人工阅读
- **上下文丰富**: 包含足够的问题诊断信息
- **性能考虑**: 避免日志影响系统性能

### 4. 循环优化
- **自动化**: 自动化重复性任务
- **工具化**: 使用合适的工具提高效率
- **标准化**: 建立团队统一的工作流
- **持续改进**: 基于反馈不断优化流程
